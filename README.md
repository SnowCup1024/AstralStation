# 星间驿站

私人 Windows 游戏工具箱，C# / WinUI 3，简体中文。当前版本 **Alpha 10.5**，暂不添加许可证。

10.5 修复安装器每次完整覆盖的问题：区分全新安装、更新和同版本修复，兼容已有 Inno 卸载登记找回安装目录，并阻止降级。使用 Inno Setup 内置校验和 Check 回调跳过内容相同的文件，只替换变化或补齐缺失文件；文件独立压缩，更新无需解压整包。继续使用 [Inno Setup](https://jrsoftware.org/isinfo.php) 统一安装、更新和卸载，只交付一个 `AstralStation-Alpha-10.5-Setup.exe`。

## 安装、更新与卸载

- 首次打开显示欢迎页，安装目录为空，必须手动选择；点击“安装”前会显示目录和操作确认。拒绝静默安装，也不接受命令行代替首次目录选择。
- 更新使用同一个 Setup，自动识别已安装版本并预填已有目录，在欢迎和确认页明确显示更新或修复。保留原安装目录；标准卸载登记可在自定义登记缺失或主程序缺失时恢复识别。相同版本用于修复，旧版不能覆盖新版。更换位置应先卸载并保留数据，再重新选择目录。更新和卸载会请求已有主窗口真正退出，绕过关闭到托盘；若正在交互、保存失败或 Steam 等待进程仍在运行，则停止操作并提示重试，不强制结束进程。应用内可检查新版发布包、打开下载页或打开本地 Setup。
- 安装器仍包含首次安装所需的完整文件，更新时在解压前比较已安装文件，只写入内容变化、新增或损坏/缺失的文件。文件没有变化就保留原文件及其时间信息，不依赖文件时间判断；用户数据与未知文件保留。安装器文件本身仍是完整包，不是独立差分下载包。
- 程序文件放在用户选择的目录，不再使用 AppData 作为默认程序目录，也不创建 current / packages 版本副本。
- 安装后提供标准卸载程序，同时登记在 Windows 已安装应用和开始菜单。卸载时选择“保留数据（推荐）”或“同时删除本地数据”；删除需要二次确认，静默卸载始终保留数据。
- 默认本地数据在 `%LOCALAPPDATA%/AstralStation`，包括 Launch 的任务、状态、设置、历史、备份，以及 SteamLaunch 的启动配置和已有自定义脚本。卸载删除选项只处理这个默认数据目录，自定义 `--data-dir` 目录保留，不删除游戏或 Steam 文件。
- 从旧版一键安装迁移时，先卸载旧版并保留数据，再运行新版 Setup。安装器尚未签名。

## 构建

使用 global.json 指定的 .NET SDK、Windows SDK 10.0.26100 和官方 Inno Setup 7.1 编译器。准备好编译器后运行：

```powershell
./Build.ps1 -InnoCompiler "ISCC.exe 的完整路径"
```

如果 ISCC.exe 已在 PATH 中，可直接运行 `./Build.ps1`。脚本只做本地发布和编译，不下载或运行工具安装器。输出为：

`.build/Alpha-10.5/AstralStation-Alpha-10.5-Setup.exe`

自包含 Windows x64，无需另装 .NET 或 Windows App SDK。临时发布目录在 `.build/Stage`，交付后清理；不向版本库提交构建产物。版本元数据统一在 Directory.Build.props。发布更新时只需把同一个 Setup 上传到 GitHub Release，标签使用 `v1.0.0-alpha.105` 这样的递增项目版本。

## 功能与数据

- 启动管理：今日队列和任务库，按完成状态显示启动/重试、标注/重置操作。支持程序、快捷方式、脚本与推荐添加，默认本地 04:00 重置。
- 运行日历：独立侧边栏页面，展示队列与后台记录并标明来源。队列按任务的每日重置时间归档，后台按观测开始的本地日期归档。同一游戏重叠或前段结束到后段开始间隔小于 5 分钟的记录合并显示；恰好 5 分钟及不同游戏不合并，跨日合并保留最早记录的归属日期。显示完整时间跨度及来源，不叠加重复观测为总时长；原始文件保留。
- 实时进程监测：今日队列自动同步，也可手动或推荐添加，移出队列会停止对应自动项，手动项和历史保留。首次自动加入时默认启用后台，已有关闭设置保留。快捷方式或脚本按任务所选进程名等待识别，记录保存实际 EXE 路径与进程身份。独立后台随登录启动，启动后先检测一次，此后每 30 秒检测一次；关闭主应用后继续记录，所有检测进入日历。启动和退出可能在下一轮才被观测，完整发生在两轮之间的短进程可能漏记。启动队列与 Steam 等待进程仍按原有时序响应。
- Steam 启动国服：账号与路径、空 EXE、ACF、启动选项四步。禁止覆盖非空 EXE；ACF 和运行配置修改有预览、备份及冲突检查。启动选项只供复制后手动粘贴，禁止写入 Steam 账号 VDF。新版直接运行无窗口进程，不再生成无用的 PowerShell 兼容入口；已有脚本和旧备份保留。
- 所有设置统一在总设置，主题跟随 DPI 与窗口尺寸。

任务数据位于 `%LOCALAPPDATA%/AstralStation/Launch`；独立监测数据在其 Monitor 子目录，两端分开写入以免覆盖。退出工具箱不结束游戏。只有手动打开时发现今日任务已全部完成才默认保持打开；否则任务完成后可按设置恢复窗口并显示 15 秒退出倒计时。记录保存失败、仍有运行任务或正在操作弹窗时不自动退出。

同一数据目录单实例，新版可接管旧版。`--paused` 暂停队列，`--data-dir "路径"` 使用独立数据目录，`--background` 在启用托盘时后台启动。登录启动登记指向用户选择的安装目录，不再复制程序到 Launch/Startup。

## Steam 时长联动

安装后在 Steam 启动国服页面复制新版启动选项，并在 Steam 游戏属性中手动替换旧命令。配置状态在页面显示期间每秒读取本地文件，不等待网络请求；按配置字段比较，忽略 JSON 排版。未就绪时悬浮游戏卡片可查看原因，Steam 保存文件后自动刷新。

总设置开启终末地 Steam 联动时，自动从已保存的国服配置加入实际 Endfield.exe 并开启后台，无需重复填写。推荐添加也识别终末地和已保存的国服路径，不会推荐 Steam 空 EXE。后台状态自动刷新。

Steam 直接启动后台程序的 `--steam-bridge` 模式：游戏已运行就等待；未运行时复用已有官方启动器，没有启动器才打开一次。游戏存在时持续保留本进程，全部退出并经过宽限后自行结束；后台退出不结束这个等待进程。其他入口启动终末地时，后台等待 3 秒并再次确认游戏仍在运行，先在本工具数据目录写入一次性“只接管计时”请求，再调用 `steam://rungameid/4732690`，每段运行最多两次、间隔 30 秒。等待程序消费请求后绝不打开或关闭启动器；即使 Steam 响应较晚、游戏已消失，也只等待退出宽限后结束。请求不因过期而变成启动器授权；如果 Steam 完全未处理请求，下次启动可能仅消费这次接管请求，结束后再主动从 Steam 启动即可。

默认等待进入游戏 10 分钟、退出宽限 8 秒。总设置可取消尚未进入游戏的等待，游戏运行时不允许取消。只有确认游戏完整退出后，才按配置关闭本次由等待程序新开的启动器；取消、超时和异常退出都保留启动器。已有等待进程期间延后应用内安装更新。只隐藏本工具进程，Steam 自身的登录、更新界面由 Steam 管理。不注入游戏，不批量终止终端、游戏或 Steam。
